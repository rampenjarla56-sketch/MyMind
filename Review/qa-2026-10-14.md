# QA + safety review — 2026-10-14

Scope: `index.html`, `sw.js`, `manifest.webmanifest` as served from `http://localhost:8420/MyMind/`.
Method: full code read, then runtime testing in a Chromium browser at 375x812 (mobile viewport), edge-case states constructed via `localStorage['mymind.v1']` + reload and via the app's own globals, flows exercised with real clicks. Test machine timezone UTC-7. No app or design file was modified.

**Verdict in one line:** no Blockers — nothing white-screens, nothing leaves the device, no unsafe content — but 4 Majors need fixing before this is trustworthy as a nightly tool, led by a timezone bug that moves the plan at 5 p.m. instead of midnight for US users.

## Repro steps

### 1. Major — plan runs on UTC dates (`today()`, index.html line 177)
`today()` = `new Date().toISOString().slice(0,10)` returns the **UTC** date, while the countdown, dark-screen clock and alarm all use local time.
Repro (machine at UTC-7, verified live):
1. Start a plan (cur 05:30, step 30) in the afternoon. "Tonight's bedtime" shows 05:30.
2. At 17:00 local, UTC midnight passes: `today()` flips to tomorrow and `targetFor(today())` drops a step — the same evening's displayed bedtime silently jumps to 05:00. Verified: `targetFor` returns 05:30 for the local date and 05:00 for the UTC date in force after 5 p.m.
Consequences: every plan "night" boundary, the start date, log-entry dates and on-time judgments shift by up to a day depending on timezone. In UTC+ zones (e.g. India, Australia) a morning log gets stamped with the *previous* day's date and `entryOnTime` compares it against the wrong night's target. Fix: derive the date string from local time (e.g. `toLocaleDateString('sv')` or manual Y-M-D from `getFullYear/getMonth/getDate`) everywhere `today()`/`addDays` feed user-facing logic.

### 2. Major — empty time input saves NaN plan (savePlan, line 443)
1. Open "Edit my plan" (or first-run setup).
2. Clear "Usual bedtime lately" (desktop: select + delete; Android Chrome: the field's clear control). Field value becomes `""`.
3. Tap "Start my plan".
Result (verified via real button clicks): state saved with `cur:""`; home shows **"NaN:NaN"**, countdown "Bedtime was NaN min ago", plan info "about NaN more nights". Persists across reloads until re-edited. Same applies to goal and wake fields (an empty wake also drives the alarm window and panic math to NaN). Fix: `if(!$('cur').value||!$('goal').value||!$('wake').value) return` plus an inline message.

### 3. Major — goal later than current bedtime accepted (targetFor, lines 182–186)
1. Setup with cur 23:00, goal 02:00.
Result (verified): tonight's bedtime = **02:00** and "You're at your goal bedtime. Keep it steady." The app moves someone already at a healthy 23:00 three hours later, with congratulations. For a sleep app aimed at teens this is a safety-adjacent correctness hole, not just UX. Fix: at save time, if `rel(goal) >= rel(cur)`, warn/confirm or refuse.

### 4. Major — SW caches error responses as the shell (sw.js lines 21–25)
The navigation handler does `caches.put('./index.html', copy)` without checking `r.ok`.
Repro (verified live):
1. With the SW active, navigate to `http://localhost:8420/MyMind/bogus-page` (any in-scope 404; on GitHub Pages, any mistyped link under `/MyMind/`).
2. Inspect the cache: `caches.match('index.html')` now returns **status 404 with the error page body**.
3. Go offline and open the app: the fallback serves the 404 page — the app will not load offline until the user revisits the correct URL online (it does self-repair then; localStorage data is not lost).
Fix: `if (r.ok) cache.put(...)` (and ideally only for `e.request.url` ending in the scope root). Same guard is worth adding to the asset branch (line 29–33) so a flaky 404/500 never becomes a permanent cache-first hit.

### 5. Minor — missing `log` array half-breaks home
1. `localStorage['mymind.v1'] = '{"cur":"05:30","goal":"00:30","wake":"09:00","step":30,"alarm":true,"start":"2026-08-15"}'`; reload.
Result (verified): home renders with correct bedtime, then `Uncaught TypeError: Cannot read properties of undefined (reading 'slice')` at renderHome line 197; sky empty, recent-log empty, and "Save" on the morning check-in throws (`S.log.push`). Not reachable through the UI alone, but there is zero schema validation on load — any partial/hand-edited state degrades silently. Truly corrupt JSON (`{broken`) and non-object JSON (`"hello"`) are handled fine (setup screen, no white screen).

### 6. Minor — double-logging one morning
1. Enter a time in the morning check-in, tap Save; enter another time, tap Save again.
Result (verified): two entries with the same `date`; sky says "59 nights" after 57 distinct dates + 2 dupes; duplicate stars draw at the exact same hash position so the count never matches what's visible; chart stacks dots on one x. Fix: replace (or confirm-overwrite) an existing entry for the same date.

### 7. Minor — afternoon countdown copy
tick() normalizes diff to ±12 h, so from ~1 p.m. until bedtime-12h the banner reads "Bedtime was N min ago. Start now — an imperfect night still counts" with N in the hundreds (verified: "647 min ago" at midday state). Suggest a third branch for large negative diffs: "Tonight's bedtime is 00:30 — come back this evening."

### 8. Minor — alarm fires on entering dark during the wake window
1. With alarm on and wake 09:00, at 09:10 tap "I'm tempted…" → "Put the phone down · lights out" (or reach dark any way).
Result (verified by setting wake = current time and calling goDark): `checkAlarm` runs immediately, `alarmBox` appears and the alarm tone starts — "Morning. Time to get up." while deliberately going dark. Guard: skip the alarm for the first N minutes after entering dark, or only arm it when dark was entered before the wake time.

### 9. Minor — wind-down has no exit
No step of the 5-step wind-down offers a route back home; dots aren't tappable; an accidental "Start wind-down" tap commits the user to tapping through all steps or reloading. One small ghost "exit" link would do.

### 10. Minor — disclaimer not visible on first run
The only medical disclaimer lives at the bottom of Home. The first thing a new user sees is the setup screen, with no disclaimer; the Safety note ("show 'not medical advice' in Settings/About") isn't met because there is no Settings/About. One dim line under "Start my plan" fixes it.

Flow tests that **passed** (for the record): breathing restart mid-cycle leaves no ghost timers (step text stable, single dot lit); dark → panic → "Take me to the wind-down" hides the dark screen and panic sheet and opens step 1; alarm stop accepts "  up  " (lowercase + spaces) and returns to home with oscillators stopped; the dark overlay fully blocks the morning check-in beneath it (elementFromPoint returns `#dark`); reminder button set/cancel/auto-cancel-on-plan-save all correct, and it degrades to the in-page highlight when notification permission is denied; 57-entry log renders sky in 0.8 ms and chart in 1.4 ms with clean layout; slept-time exactly at target+30 judged on-time (boundary inclusive); pre-plan-start log entries are judged against the clamped day-0 target and correctly skipped by the 14-day chart.

## Privacy

**Verdict: PASS — nothing leaves the device.**

- Runtime: after exercising setup, logging, chart, wind-down, breathing, voice, sounds, dark screen, panic, can't-sleep, alarm and reminder flows, the network log contains only same-origin GETs to `http://localhost:8420/MyMind/*` (shell + icons + manifest). Zero third-party requests.
- Static: `grep` over `index.html`, `sw.js`, `manifest.webmanifest` finds no `http(s)://` URL at all, no `fetch`/`XMLHttpRequest`/`sendBeacon`/`WebSocket`/`EventSource`/analytics anywhere except the SW's pass-through `fetch(e.request)` for the app's own assets.
- Storage: single `localStorage` key `mymind.v1` (plan + log times only — no names, no free text; brain-dump text is never persisted at all). Nothing is ever written to the URL (no query strings, no hash state).
- Notifications are local (`showNotification`/`new Notification`), no push subscription, no server. Sounds are synthesized in-page; nothing downloaded.
- One OS-level caveat, outside the app's control: `speechSynthesis` voices on some platforms are cloud-backed by the OS, so the relaxation lines could transit an OS vendor service. The lines contain nothing personal; worth a sentence in DesignNotes if the team wants to be exhaustive.
- No accounts, no cookies, no identifiers — consistent with the COPPA/GDPR-K-friendly posture in Safety and Compliance.

## Wording / safety

**Verdict: PASS with two fixes (findings 10 and 11).** Every user-visible string in `index.html` and `manifest.webmanifest` was reviewed.

- **Medical claims — PASS.** Nothing promises to treat or cure anything. Framing stays behavioral: "a plan that moves you earlier each night", "We move bedtime earlier a little each night". Borderline-but-fine causal lines: "Daylight now is what moves your clock" and "The urge peaks and passes in about two minutes" — both standard sleep-hygiene phrasing; if the team wants extra caution, soften to "helps move/usually passes".
- **See-a-doctor prompt — PRESENT**, correct wording and scope: "Not medical advice. If sleep trouble lasts for weeks or you feel low or anxious, talk to a parent or doctor." Matches the Safety note; only its placement is lacking (Home only — finding 10).
- **Shame/streak check — PASS, genuinely good.** "No shame — the chart just tells the truth", "A rough night never removes a star", "an imperfect night still counts", "Pick what fits. No wrong answer." The sky only accumulates and the moon never empties; a missed night leaves no gap, no broken streak, no red mark. No guilt language found anywhere.
- **Engagement-bait check — PASS.** The reminder is opt-in, visually demoted (`button.mini`), capped at one notification, and cancellable; the dark screen actively pushes the phone away. Nothing nags.
- **Age-appropriate tone — PASS.** Direct, respectful, never preachy; "apps are built by teams whose whole job is to keep you on them at 1 a.m." is honest without fear-mongering. The alarm's "type UP" task is explained with its reason (daylight moves the clock).
- Two wording fixes folded into findings: surface the disclaimer before a plan exists (10), and either persist the brain dump or change "It stays on this device" to something like "it isn't saved anywhere — just getting it out of your head" (11).

## sw.js update path

**Can a stale cache strand a user on an old version? No** — the design is sound: navigations are network-first (fresh `index.html` whenever online), `skipWaiting()` + `clients.claim()` activate a new SW immediately, and `activate` deletes all caches except the current `mymind-vN`, so bumping the version on each ship replaces stale shells. Non-navigation assets (icons, manifest) are cache-first forever, which is fine *only* as long as the cache name is bumped on every release — keep that rule in the ship checklist.
The one real defect in this file is finding 4: responses are cached without an `r.ok` check, so a single in-scope 404/500 poisons the offline shell (and, on the asset branch, pins an error response permanently until the next version bump).
